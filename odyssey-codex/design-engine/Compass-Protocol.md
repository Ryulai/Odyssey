# Framework

## Definition

A Framework defines the structural skeleton of a concept or system.

It does not define calculations, rules or user interface.

Instead, it defines how every component should be organised so that different systems remain consistent across the Odyssey ecosystem.

Frameworks exist to standardise thinking before implementation.

---

# Purpose

Every profession, system and feature should follow a common structure.

Without a Framework, every designer will build systems differently.

Consistency is more valuable than complexity.

---

# Why

As Odyssey grows, more professions and systems will be added.

Examples:

- Hunter
- Waiter
- Bartender
- Cashier
- Store Manager
- Mentor

Each profession may have different calculations.

However,

their structures should remain consistent.

Frameworks ensure every future system follows the same design language.

---

# What is NOT

A Framework is NOT:

- A System
- A Formula
- A KPI
- A Rule
- A UI Design
- A Database Structure

Framework only defines structure.

# Design History

Originally,

Framework was considered part of each individual system.

After discussion,

it became clear that Framework is an independent design layer shared by every system.

This significantly improves consistency and future scalability.

---

# Current Discussion

Current consensus:

Every major system should have its own Framework before Formula design begins.

Formula should never be designed before the Framework is stable.
